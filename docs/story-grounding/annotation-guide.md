# Annotation guide

For anyone adding to `corpus/story_v1`. Read [schema.md](schema.md) first. Write
examples in `dev_examples.py`; `heldout_examples.py` is frozen (see
[evaluation.md](evaluation.md)). Run `python3 -I corpus/story_v1/build.py` to rebuild;
it rejects a token that is not in the text where you said it is.

## Provenance

Every example is text **you wrote**, not text generated by an AI service (rights, and
the terms of such services, make generated text unsafe as an evaluation or training
set) and not text from a manuscript without the author's explicit consent. Say who
wrote it at the top of the file.

## 1. Tokens

1. Tokenise as UD does: `didn't` → `did` `n't`; `Mara's` → `Mara` `'s`. Quotes and
   punctuation are tokens.
2. Tag with the 15 UPOS tags only. If unsure between two, decide by what the word does
   *in this sentence*, not by what it usually is.
3. Participles used as modifiers before a noun are `ADJ` (`the broken lantern`); after
   `be` with a following agent or no complement, `VERB` (`was hidden`).
4. `to` before a base verb is `PART`; before a noun phrase `ADP`.
5. `not`, `n't` are `PART`. `never` is `ADV`.
6. A name is `PROPN` even when it is also a word (`Rowan rowed the boat`).
7. Lemma: lower-case, base form; `PROPN` keeps its case. Don't lemmatise `AUX`/`n't`
   (they stay as written in this corpus).

## 2. Entities

- Give a stable id: `char_`, `place_`, `item_`, `group_`, `time_`, `event_` + the words
  that name it, lower-case, underscores. `the silver key` → `item_key` (adjectives are
  not part of the id); `the chapel floor` → `place_chapel_floor`.
- Characters come from `project_entities`. A capitalised name that is not there is a
  *new* character: give it `char_<name>` and expect the pipeline to flag it.
- A word that can be an item or a place (`gate`, `door`) is **one** thing: don't try to
  decide, the matcher ignores `item_`/`place_`.
- A time word (`dawn`, `storm` after `before/after/during`) is not an entity; it is the
  fact's `time` text.

## 3. Facts

1. One fact per clause: subject, relation, object and the slots the clause fills.
2. **Passive**: `subject` is the agent if stated (`by Iven`), else null; `object` is the
   thing acted on. The fact is the same as the active sentence's.
3. **Negation**: keep the fact with `polarity: negated`. Never also add the positive
   event. `could not`/`would not` are negations; `might not` is `possible`.
4. **Modality**: `might`, `may`, `could`, `would`, `perhaps`, `maybe` → `possible`. A
   possibility is not an event.
5. **Attribution**: a clause after `told X that`, `said that`, or inside quotation marks
   is the speaker's, `kind: reported`; after `believed/thought/suspected that` it is
   `kind: belief`. The verb of saying itself is not a fact. A character's claim is not
   the narrator's.
6. **Pronouns**: resolve to a character only if exactly one defined character with that
   pronoun was mentioned in this sentence or the one before. If two could be meant, set
   `subject: null` and `unresolved_subject: true`. Do not guess. `it` resolves to the
   single item mentioned, or the one that was the object of the last action; otherwise
   unresolved.
7. **Coordination**: `Edda and Iven carried it` is two facts (one per subject);
   `took the key and the map` is two facts (one per object).
8. **Motion into a place**: `entered the hall` → `destination`, not `object`.
9. **Attributes**: colours and materials before a noun are their own `be` fact.
10. A question in the source text yields no fact.

## 4. Answers

Decide the status from the evidence, not from how sure the sentence sounds.

| Status | Use when |
|---|---|
| `STATED` | A selected source says it, in any wording, including passive and paraphrase |
| `DERIVED` | It follows from stated facts by a rule you can name (`hid X in Y` → X is in Y). If a later fact moves it, it is `UNKNOWN` with note `later moved`, not derived |
| `UNKNOWN` | The sources don't answer. Evidence is empty (silence; `offer_proposal: true`) or the facts that exist are cited (`note` says why) |
| `CONFLICT` | Two sources give incompatible answers. Give both in `answers` and cite both |
| `PROPOSED` | Never in a corpus answer; only proposals have it |

Evidence ids list every `source_id` the answer relies on, no more.

## 5. Review

Two passes. The second reader labels the same sentences **without** seeing the first's
labels, then differences are discussed and each resolved case that isn't obvious is
added to this guide. Record the agreement (token-level POS agreement; fact exact-match
agreement). *This has not been done for the starter corpus*: it was written and labelled
by one author.
